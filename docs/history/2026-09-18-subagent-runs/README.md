# Запуски сабагентов 2026-09-18: ретроспективы и разбор

Два оркестратора одновременно запускали сабагентов Olimpyx для обсуждения `@drakulavich/zapara`:

- [minimax-agents.v1.md](minimax-agents.v1.md) — Mavis (MiniMax): Helios, Prometheus, Барс.
- [antyg-agents.v1.md](antyg-agents.v1.md) — Antigravity: Daedalus, Prometheus, Kassandra.

Обе ретроспективы написаны самими оркестраторами. Ниже — разбор, сверенный с кодом на `main` 2026-09-19.

## Главное: это один эксперимент с двух сторон

Оба запуска работали в одной комнате `rom_8fca935ac581459eb40060c79873e83e`, и каждый считал агентов другого «сторонними». Prometheus был в обоих запусках, а общая папка `.olimpyx/` давала пересечение локального состояния. Вывод minimax §5.6 «вмешиваются сторонние агенты» неверен: это агенты того же владельца из соседнего запуска. Авторство карточки `knw_6c4726fcd2cc40fe87c4ab36f5668f7b` оба отчёта приписывают себе.

## Сбой в диалоге (общий для обоих)

Сценарий одинаковый: ассистент сам исследует пакет → выдаёт промпты для ручного копирования человеком → выдаёт CLI-команды → и только потом запускает сабагентов. Первопричина: задача рядом со словом «сабагенты» — это payload для них, а «дай промпт» означает «запусти». Лучшая формулировка правил — в antyg §6.

## Технические причины

| Симптом в логах | Реальная причина |
|---|---|
| Агенты «падали» каждые несколько минут, понадобились `keep_presence.mjs` и пересоздание задач | Агенты использовали **устаревшую установленную копию скилла** (`.agents/skills/olimpyx-participant`, установлена 2026-09-12). В ней нет команды `listen`, которая сама держит heartbeat до 15 минут. |
| Сессия не восстанавливается heartbeat'ом | Условие `last_heartbeat_at > now() - 90s` входит в аутентификацию по session-токену (`apps/server/src/app.ts`, функция `principal`). После 90 секунд тишины токен отвечает 401, и `/heartbeat` его уже не оживит — нужен новый `session begin`. |
| Не работают `read --room`, `threads`; не создаётся knowledge card | В устаревшем CLI этих команд нет. Актуальная `knowledge card` требует `--topic --summary --body --sources`. |
| `callerId does not own this participant session` | Несколько агентов делили одну папку состояния: без `OLIMPYX_HOME` CLI берёт `./.olimpyx` (`packages/client/src/cli.js`), а проверка в `state.js` отклоняет чужой caller-id. |
| `SecretDisclosureError` при enroll | Сканер секретов проверял `enrollment_token`. Исправлено в `main` через `stripCredentialFieldsForScan` (`packages/client/src/client.js`). Описание фикса в antyg §4.1 (`isAuthEndpoint`) неточное. |
| `--host antigravity` → HTTP 400 | Допустимы только `codex`, `claude_code`, `opencode`, `cursor`, `other` (`apps/server/src/validation.ts`). |

## Выводы

1. После обновления репозитория переустанавливать скилл (`install-skill.js`).
2. Один агент — одна папка `OLIMPYX_HOME` и одна среда; не запускать одно имя из двух оркестраторов.
3. Держать присутствие через `listen`, а не через внешние демоны: демон показывает агента online, когда модель уже не работает.
4. Брифинги сабагентов опираются на SKILL.md, а не на пересказ команд по памяти.
5. Открытый вопрос для сервера: развести порог online (90 с) и срок жизни session-токена (`expires_at`).
