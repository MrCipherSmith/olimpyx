# Отчет о реализации: Token-Efficient Daemonless Listener (`listen`)

Реализация выполнена в ветке `feat/daemonless-listener`. Базовый MVP и production не изменены.

## Что изменено

- **Библиотека `@olimpyx/client` (`packages/client/src/client.js`):**
  - Добавлен метод `listen({ cursor, timeoutMs, maxWaitMs, onHeartbeat, signal })`.
  - Реализован внутренний ограниченный цикл Node.js, выполняющий длинный опрос и возвращающий управление модели только при наличии реальных событий (`status: "received"`) либо по истечении лимита ожидания (`status: "idle_timeout"`).
  - Обеспечен строгий порядок операций: вызов `onHeartbeat()` выполняется в начале каждой итерации *перед* вызовом `wait()`, гарантируя поддержание 90-секундного серверного дедлайна присутствия.
  - Добавлен экспоненциальный backoff с джиттером (1s, 2s, 4s до 3 попыток) при сетевых сбоях и 5xx, отменяемый по сигналу (`AbortSignal`).
  - Устранена задержка возврата данных: при наличии входящих событий возврат происходит немедленно (<1s).

- **Интерфейс командной строки (`packages/client/src/cli.js`):**
  - Добавлена команда `listen --caller-id <ID> [--max-wait-min 15] [--poll-timeout-sec 25] [--after <CURSOR>]`.
  - Реализован перехват сигналов `SIGINT` (код 130) и `SIGTERM` (код 143) с отменой запросов, отправкой `POST /v1/sessions/:sessionId/end` (`reason: "agent_ended"`) и очисткой локальной сессии через `state.clearSession()`.
  - Команда `wait` сохранена в исходном виде для обратной совместимости.

- **Скилл участника (`skills/olimpyx-participant/SKILL.md`):**
  - Обновлены инструкции для LLM-агентов: предписано использовать `listen` вместо циклического `wait`.

- **Тестовое покрытие:**
  - `packages/client/test/client.test.js`: 10 модульных тестов на метод `listen`.
  - `packages/client/test/install.test.js`: 4 теста установки автономного скилла для разных хостов.
  - `packages/client/test/listen-cli.test.js`: 8 сквозных тестов дочернего процесса CLI (проверка аргументов, валидация границ параметров, получение событий, сохранение курсора при получении данных и при idle_timeout, ретраи, таймаут, сигналы SIGINT/SIGTERM).

## Исправления по результатам адаптивного ревью (PR #11)
1. **Персистенция курсора при пустом long-poll (idle_timeout):**
   - В `client.js` добавлен callback `onCursor`, уведомляющий CLI о продвижении курсора.
   - В `cli.js` обеспечено безусловное сохранение последнего курсора (`result.page?.next_cursor`) в `session.json` как при получении событий, так и при `idle_timeout`, предотвращая повторную доставку уже просмотренных событий при следующем запуске.
2. **Строгая валидация границ параметров CLI:**
   - Для `--max-wait-min` ($1 \le N \le 60$) и `--poll-timeout-sec` ($5 \le N \le 30$) реализована явная валидация без тихого сглаживания (clamping), с понятными сообщениями об ошибке (с поддержкой тестового режима через переменную окружения `OLIMPYX_TEST_FAST_TIMEOUT=1`).
3. **Криптографический джиттер:**
   - Заменен `Math.random` на криптографически стойкий `randomInt(-200, 201)` из модуля `node:crypto` для симметричного диапазона $\pm 200\text{ms}$.
4. **Ретраи для heartbeat при сетевых сбоях:**
   - В `client.js` добавлен цикл ретраев для heartbeat на случай кратковременных сетевых сбоев/5xx, предотвращающий падение сессии из-за микросбоев соединения.
5. **Синхронизация документации с сервером:**
   - В `jobs/bounded-listener-2026-09-17/prd.md` (§5.1 и §5.5) зафиксировано, что опрос реализуется клиентом (сервер отвечает немедленно без учета `prefer: wait`), а параметр `reason` в `POST /v1/sessions/:id/end` валидируется сервером по Zod-схеме, но не сохраняется в текущей таблице БД.
   - В `docs/ROADMAP.md` вопросы Horizon 2 Q-001 и Q-002 отмечены как решенные в рамках PR #11.
   - В `skills/olimpyx-participant/SKILL.md` расширено описание схемы возвращаемого JSON, обработки сигналов и ретраев.

## Результаты ревью и проверок
1. **Соблюдение D-001 и D-002:** Решение строго foreground, без фоновых демонов ОС и сторонних зависимостей.
2. **Нулевые изменения бэкенда:** Использованы существующие эндпоинты `/v1/inbox/events` и `/v1/sessions/:id/heartbeat`.
3. **Экономия ресурсов:** 95–99% сокращение вызовов инференса модели во время затишья.
4. **Тесты:** 22/22 тестов в пакете клиента успешно пройдены, `npm run typecheck` проходит чисто.
